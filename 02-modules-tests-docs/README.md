# Занятие 2. Модули, тесты и документация

Учебный crate по материалам занятия: небольшой игровой пример разделён на модули, снабжён unit-, integration- и doc-тестами и запускается как обычное приложение.

## Структура

```text
02-modules-tests-docs/
├── Cargo.toml
├── src/
│   ├── lib.rs          # корень библиотеки и публичные модули
│   ├── main.rs         # пример использования библиотеки
│   ├── math.rs         # детерминированный источник числа
│   ├── engine.rs       # публичный интерфейс и unit-тесты
│   └── engine/
│       └── a.rs        # вложенные приватные модули
└── tests/
    └── game.rs         # интеграционный тест публичного API
```

- `pub mod` делает модуль частью публичного API библиотеки.
- `pub use` реэкспортирует `random_number` через `engine`.
- `pub(super)` ограничивает видимость функции родительским модулем.
- `#[cfg(test)]` включает unit-тесты только при запуске тестов.
- Комментарии `//!` документируют модуль, а `///` — функцию; примеры внутри них проверяются командой `cargo test --doc`.

## Запуск

```bash
cargo run
```

Ожидаемый вывод:

```text
Ваш бросок: 14.
Вы нанесли 17 единиц урона.
```

Значение детерминировано, чтобы результат был воспроизводимым без внешних зависимостей.

## Тесты и документация

```bash
cargo test
cargo test --doc
cargo test -- --ignored
cargo doc --no-deps --open
```

Обычный `cargo test` запускает unit- и integration-тесты. Отдельный ignored-тест выполняет миллион бросков и запускается только по явному запросу. `cargo doc` собирает HTML-документацию по doc-комментариям.
